# 資料庫建置方式及資料來源說明

## KPOP_GROUPS、KPOP_IDOLS 資料表

關於 KPOP_GROUPS、KPOP_IDOLS 資料表內的資料建置方式，我們首先利用爬蟲從 Kprofiles.com 網站收集 K-pop 團體與偶像的資料。爬蟲腳本會自動從 Kprofiles.com 的各個分類頁面（包括女團、男團、混聲團體、雙人組合、個人歌手等）提取團體的 profile 連結，並逐一訪問這些頁面來抓取詳細資訊。

對於 KPOP_GROUPS 資料表，我們從每個團體頁面中提取以下資訊：團體名稱（英文與韓文）、出道日期、經紀公司、團體類型（B=男團、G=女團、M=混聲）、成員數量、Logo 圖片 URL，以及團體描述。由於部分爬蟲後得到的團體資料可能缺乏某些欄位（如韓文名稱、Logo 圖片、描述等），因此這些欄位可為空值。

對於 KPOP_IDOLS 資料表，我們從團體頁面中提取每個成員的資訊，包括藝名（英文與韓文）、國籍、出道日期等。腳本會自動從成員的 Facts 區塊中提取國籍資訊，優先匹配 "born in" 的具體地點資訊以提高準確性。由於部分成員的國籍資訊可能無法從頁面中提取，因此該欄位可為空值。此外，腳本會根據 `stage_name`、`nationality`、`debut_date` 三個欄位判斷是否為重複偶像，避免重複插入相同的偶像資料。

爬取完成後，我們將資料匯出為 JSON 格式（如 `girl-groups-batch1.json`），接著使用 `import-girl-groups.ts` 腳本將團體資料匯入至資料庫的 KPOP_GROUPS 資料表，並使用 `import-idols-from-groups.ts` 腳本將偶像資料匯入至 KPOP_IDOLS 資料表，同時在 GROUP_IDOL 資料表中建立團體與偶像的關聯關係。

## KPOP_SONGS 資料表

KPOP_SONGS 資料表內的資料建置方式，我們利用 Spotify API 來獲取 K-pop 歌曲的資料。腳本會根據指定的藝人名稱或搜尋關鍵字，透過 Spotify 的搜尋 API 來查詢相關歌曲。在藝人模式下，腳本會先查詢藝人資訊，然後使用 `artist:ID` 語法來精確搜尋該藝人的所有歌曲，並過濾只保留主要藝人是目標藝人的歌曲（排除合作歌曲、翻唱等）。

從 Spotify API 取得的歌曲資料包括：歌曲名稱、發行日期、歌曲長度（毫秒）、Spotify 連結等。腳本會自動從歌曲名稱中分離英文和韓文部分，並移除可能包含在歌曲名稱中的藝人名稱（如 "TWICE - 歌名" 格式）。對於發行日期，Spotify API 可能返回不同格式（YYYY-MM-DD、YYYY-MM 或 YYYY），腳本會自動補全為完整的日期格式。

由於 Spotify API 不提供 YouTube 連結，因此 `youtube_original_url` 欄位在匯入時會先設為 placeholder，需要後續手動補上真正的 YouTube MV 連結。此外，`difficulty_level` 欄位在匯入時會設為預設值 5（中等難度），可根據實際情況後續調整。如果歌曲名稱中沒有韓文，`title_kr` 欄位會使用與 `title` 相同的值。

匯入完成後，腳本會自動建立歌曲與團體的關聯（SONG_GROUP 資料表）以及歌曲與偶像的關聯（SONG_IDOL 資料表），這些關聯是根據 Spotify 回傳的藝人資訊與資料庫中已存在的團體和偶像資料進行匹配。

## USERS 資料表

USERS 資料表內的資料建置方式，則採取隨機生成的方式，共生成多個使用者帳號。每個使用者包含以下資訊：使用者名稱、電子郵件、密碼、生日、性別、地區、電話號碼、帳號狀態、建立時間、最後登入時間，以及角色（一般使用者或管理員）。使用者 ID（u_id）使用時間戳加上隨機數的方式生成，確保唯一性。

## PROJECT 資料表

PROJECT 資料表內的資料建置方式，我們利用已生成的使用者模擬使用者建立專案的行為。每個專案會隨機挑選一首歌曲（從 KPOP_SONGS 資料表中選擇）、設定專案標題、目標成員數量、練習地點、專案狀態、描述等資訊。專案的建立時間和更新時間會隨機生成，專案狀態可能為 'A'（進行中）、'D'（已刪除）或 'F'（已完成）。

## 其他關聯資料表

對於 SONG_GROUP、SONG_IDOL、GROUP_IDOL 等關聯資料表，資料是透過腳本自動建立的。當匯入歌曲資料時，腳本會根據 Spotify 回傳的藝人資訊，在資料庫中查找對應的團體和偶像，並自動建立關聯關係。如果找不到對應的團體或偶像，則不會建立該關聯。

對於 PROJECT_TARGET、PROJECT_MEMBERS、PROJECT_APPLICATIONS、PRACTICE_SCHEDULE 等與專案相關的資料表，資料是透過模擬使用者行為來生成的。系統會為每個專案隨機生成目標位置（對應到特定的偶像）、專案成員、申請記錄，以及練習時間表。在生成練習時間表時，系統會確認挑選的時段是否有重疊，若有則會捨棄該筆資料，確保資料的合理性。
